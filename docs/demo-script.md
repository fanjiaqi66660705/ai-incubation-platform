# 科创星火 — 面试演示脚本

> 总时长约 6 分钟。提前 10 分钟完成「演示前检查清单」。

---

## 演示前检查清单

- [ ] 笔记本电量充足 / 接电源
- [ ] 浏览器全屏，关闭无关标签页
- [ ] Dev server 已启动（`npm run dev`），或 Vercel 部署地址可访问
- [ ] 打开以下页面并确认正常：
  - [ ] 首页 http://localhost:3000
  - [ ] 项目展示 http://localhost:3000/projects
  - [ ] AI 评估 http://localhost:3000/evaluate
  - [ ] 资源检索 http://localhost:3000/resources
- [ ] 如果用 GLM 真实模式：确认 `.env.local` 中 `ZHIPU_API_KEY` 已填入
- [ ] 网络稳定（评估和检索需要联网调 GLM API；演示模式可离线）
- [ ] 手机静音，关闭通知

---

## 第一幕：开场（30 秒）

**话术**：

> 「这是我开发的科创星火平台——一个 AI 驱动的校内科创项目孵化展示平台。
> 我们发现很多同学有科创想法但不知道从何开始，也有团队做了项目但缺少曝光。
> 这个平台用 AI 解决两个核心问题：**项目评估**和**技术资源检索**。」

**操作**：打开首页，让面试官看到 Hero 区域和统计数据。

**要点**：
- 手指统计条：「目前已收录 X 个项目，覆盖 AI 应用、Web 平台、小程序、硬件 IoT、数据科学五个方向」
- 指向能力卡：「四个核心模块，其中 AI 评估和资源检索已经上线」

---

## 第二幕：项目展示中心（1 分钟）

**操作**：点击导航栏「项目展示」。

**话术**：

> 「项目展示中心收录了校内的优秀科创项目。支持按分类筛选——比如只看 AI 应用——也可以按状态筛选，看哪些还在孵化中、哪些已经上线。」

**操作**：
1. 演示分类筛选（点「AI 应用」）
2. 演示状态筛选（点「孵化中」）
3. 在搜索框输入「知识库」，展示实时搜索
4. 点击「智课伴侣」卡片进入详情页

**话术**（详情页）：

> 「每个项目有完整的详情页——进度条、里程碑时间线、技术栈标签。这个页面是静态预渲染的，首屏加载非常快。」

**要点**：
- 滚动展示里程碑时间线
- 指向相关项目推荐

---

## 第三幕：AI 评估引擎（2 分钟）⭐ 核心亮点

**操作**：点击导航栏「AI 评估」。

**话术**：

> 「这是平台的核心模块——AI 项目评估引擎。粘贴一份项目计划书，AI 会从五个维度量化打分，生成雷达图和一份可执行的孵化建议。」

**操作**：
1. 点击「填入示例」（自动填充智课伴侣的项目描述）
2. 点击「开始 AI 评估」
3. 等待评分结果出现

**话术**（等待时）：

> 「AI 正在阅读计划书……评分结果出来了——总分 70，等级 B。右侧是五维雷达图，可以直观看到这个项目在社会价值和创新性上得分高，但完成度有短板。」

**操作**：
4. 滚动展示维度明细和雷达图
5. 等待流式建议生成（打字机效果）

**话术**（建议流出时）：

> 「最下面这份孵化建议是逐字流式生成的——用的是 SSE 服务端推送。建议分三部分：核心优势、关键风险、下一步行动清单。每条建议都标注了建议周期，可以直接落地执行。」

**技术点**（如面试官追问）：

> 「评估分两步：第一步调 GLM 模型做结构化评分，返回 JSON 包含五维分数和评语；第二步根据评分结果流式生成 Markdown 格式的孵化建议。中间有一层数据清洗兜底，确保模型输出异常时页面不会崩溃。」

**备用话术**（如果 API 超时或无 Key）：

> 「当前使用的是演示模式——本地基于文本特征的确定性评分算法。配置 API Key 后会切换到 GLM-4 实时评估。演示模式的交互流程和 UI 完全一致。」

---

## 第四幕：AI 资源检索（1.5 分钟）

**操作**：点击导航栏「技术资源」。

**话术**：

> 「第三个模块解决的是另一个痛点——想做一个项目但不知道用什么技术、参考什么开源项目。这里用自然语言对话就能检索。」

**操作**：
1. 点击一个示例问题（如「我想做一个课程知识库问答项目，有什么开源项目可以参考？」）
2. 等待结果加载

**话术**（结果出现时）：

> 「AI 从资源库中匹配到了 LangChain-Chatchat——这是做知识库问答最常用的开源模板。每张卡片有匹配度评分、推荐理由、标签和热度。下方还有一段流式生成的推荐解读，告诉你从哪个开始、怎么用。」

**操作**：
3. 在输入框手动输入「有哪些含金量高的科创竞赛？」，按 Enter
4. 等待第二轮结果

**话术**：

> 「可以多轮追问。这次检索的是竞赛类资源——挑战杯、数学建模、互联网+，每张卡片都附带了推荐理由。」

**技术点**（如面试官追问）：

> 「检索分两种模式：有 API Key 时，把整个资源目录发给 GLM 做语义匹配；无 Key 时走本地关键词加权检索——标签命中权重最高，标题次之，描述最低。匹配度评分经过归一化处理，保证不同查询间的可比性。」

---

## 第五幕：技术架构（45 秒）

**话术**：

> 「简单说一下技术架构。前端是 Next.js 15 + React 19 + Tailwind CSS v4，深色科技感主题。AI 层封装了智谱 GLM-4 的 OpenAI 兼容接口，两个核心接口——评估和检索——都走 SSE 流式推送，前端手动解析事件流。」

**操作**：回到首页，指向能力卡。

**话术**：

> 「设计上有一个关键决策：**优雅降级**。不配置 API Key 时，平台自动切换到演示模式——本地算法生成确定性结果，所有交互流程完整可用。这意味着即使在没有网络的环境下，演示也不会翻车。」

---

## 第六幕：收尾（30 秒）

**话术**：

> 「后续路线图包括：接入真实项目数据库、用户认证与项目提交、团队协作看板。
> 做这个平台的原因是——我自己就是科创竞赛的参与者，深知立项前的迷茫和资源检索的低效。我希望用 AI 技术降低科创的门槛，让更多同学敢想敢做。」

## Q&A 预备

| 可能的问题 | 回答要点 |
|------------|----------|
| 为什么选 GLM 不用 GPT？ | 国产模型、免费额度、OpenAI 兼容接口方便切换 |
| SSE 和 WebSocket 的区别？为什么用 SSE？ | SSE 单向推送更轻量，HTTP 协议无额外握手，适合 AI 流式输出场景 |
| 数据存在哪里？ | 目前是 Mock JSON，预留了 Prisma 切换路径，评估和检索逻辑不需要改 |
| 演示模式怎么实现的？ | 无 Key 时走本地算法——文本特征提取 + 确定性评分 + 关键词加权检索，保证演示不翻车 |
| 雷达图用什么做的？ | Recharts RadarChart，响应式，支持暗色主题 |
| 如果模型输出格式不对怎么办？ | normalizeEvaluation 清洗兜底：提取 JSON、约束分数范围、缺失字段填默认值 |

## 应急预案

| 场景 | 预案 |
|------|------|
| GLM API 超时 | 「当前网络较慢，切换到演示模式」→ 重启 dev server（无 Key 即为演示模式） |
| 页面白屏 | 刷新页面；如持续白屏，检查 dev server 是否在运行 |
| 端口被占 | `npx kill-port 3000` 后重启；或改用 `npm run dev -- -p 3002` |
| 完全无网络 | 演示模式可离线运行，提前确认 `.env.local` 中 Key 为空 |
